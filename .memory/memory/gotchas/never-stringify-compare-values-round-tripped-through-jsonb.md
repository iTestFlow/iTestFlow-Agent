Postgres jsonb canonicalizes object key order (length-first), so any value written to a jsonb column and read back has different key order than the object that was stringified in. Comparing JSON.stringify(readBack) === JSON.stringify(freshObject) is therefore always false for multi-key objects — the Playwright execution drift check did exactly this and would have errored every run on real Postgres while unit tests (which mocked the read in insertion order) stayed green. Compare field-by-field instead, and when mocking a jsonb read in tests, deliberately reorder the keys so a stringify-equality regression fails.
