The /test-execution page is a four-step workbench (Setup, Test Cases, Review & Execute, Results) built on the shared WorkflowStepper. Runs remain immutable server-side; all authoring lives in a client-side draft persisted per project in localStorage with secret values stripped. 'Approve & Execute' posts the final payload (baseUrl required, executionNotes, screenshotPolicy, testData, nullable plan/suite provenance, caller-supplied cases). Rerun = fetch run detail, rebuild the draft (draftFromRunDetail), edit, create a new run. This preserves the one-active-run-per-project partial unique index; the 23505 violation maps to a friendly 409.
